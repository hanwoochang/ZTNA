# ZTNA 위험도 산출(CARTA) 및 대응 체계

본 문서는 ZTNA 정책 서버(`ztna-policy-server/services/riskEngine.js` 및 `controllers/authController.js`)에 구현되어 실제 동작하는 **실시간 컨텍스트 기반 위험도 평가 로직(CARTA: Continuous Adaptive Risk and Trust Assessment)**을 상세히 명세합니다.

---

## 1. 위험도 점수 산출 테이블 (Risk Assessment Rules)

| 카테고리 | 평가 항목 (컨텍스트 트리거) | 부여 점수 | 적용 및 대응 (Action) |
| :--- | :--- | :---: | :--- |
| **기기 무결성** | **모바일 루팅/탈옥 감지 (`checkDeviceSecurity` 및 `isRooted: true`)** | **즉시 차단** | 모바일 클라이언트(`utils/deviceSecurity.ts`)가 로그인 직전 및 30초 Heartbeat마다 `Device.isRootedExperimentalAsync()`로 탐지하여 즉시 차단 화면(`BlockedScreen`)으로 전환하며, 서버(`POST /api/login`)도 `isRooted: true` 수신 시 `403`으로 즉시 거부함 |
| **기기 신뢰도** | **관리자에 의해 차단/해제된 기기 (`status` 가 `BLOCKED`)** | **즉시 차단** | `forceDeny` 및 `+100점` |
| **기기 신뢰도** | **컴플라이언스 위반 기기 (`is_compliant = 0`)** | **즉시 차단** | `forceDeny` 및 `+100점` (이 값을 갱신하는 자동 탐지 로직은 아직 없음) |
| **기기 신뢰도** | **시스템에 등록되지 않은 신규 기기 접속** | **+30점** | `STEP_UP`: 이메일 OTP 인증 후 `PENDING`으로 등록되어 어드민 승인 대기 |
| **기기 신뢰도** | **이미 `PENDING` 상태인 기기로 로그인** | **점수 계산 전 종료** | `202 requiresApproval` 반환, 감사 로그에는 `DENY`(30점)로 기록, OTP는 발송하지 않음 |
| **물리적 이동** | **물리적으로 불가능한 이동 속도 (1,000km/h 초과)** | **+70점** | Impossible Travel 감지, 총점 70점 이상으로 즉시 차단 (`DENY`) |
| **물리적 이동** | **비정상적인 고속 이동 패턴 (500~1,000km/h)** | **+30점** | 위험도 가산 및 2차 인증(OTP) 요구 |
| **물리적 이동** | **이전 접속지 대비 장거리 이동 (500km 초과)** | **+20점** | 위험도 가산 |
| **물리적 이동** | **이전 접속지 대비 중거리 이동 (100~500km)** | **+10점** | 위험도 가산 |
| **네트워크** | **기기의 마지막 접속 IP와 다른 IP로 접속** | **+20점** | 위험도 가산 |
| **네트워크** | **모바일 앱의 GPS 위치 정보 수집 불가/권한 거부 (등록된 기기)** | **+15점** | 위험도 가산 |
| **접속 시간대** | **새벽 2시 ~ 5시 사이 접속** | **+15점** | 위험도 가산 |
| **접속 시간대** | **업무 시간 외 접속 (9시 이전 또는 18시 이후, 새벽 2~5시 제외)** | **+15점** | 위험도 가산 (위 항목과 중복 가산되지 않으며 시간대 가산은 최대 +15점, 주말 판정 로직은 없음) |

---

## 2. 보안 정책 결정 임계치 (Action Thresholds)

산출된 총 위험도 점수(0 ~ 100점) 및 기기 상태에 따라 다음과 같은 3단계 정책(NIST SP 800-207 준수)이 자동 결정됩니다:

```
[ 점수 기준 ]
 0점 ──────────────── 30점 ──────────────── 70점 ────────────── 100점
  │      ALLOW         │      STEP_UP        │       DENY         │
  │   (정상 출입증)     │  (OTP / 생체 인증)    │  (접속 차단 / 튕김)  │
```

1. **즉시 차단 (`DENY` / `forceDeny` / 70점 이상)**:
   * 루팅 신고, 차단된 기기, Impossible Travel 등 심각한 위협 발생 시 토큰 발급을 거부하고 접속을 즉시 차단합니다.
   * 70점 이상 또는 `forceDeny`로 차단되면 해당 기기의 `status`가 `BLOCKED`로 전환되고 생체 인증 비밀키(`bio_token_hash`)가 폐기되어, 재승인 후에도 이메일 OTP를 다시 거쳐야 합니다.
   * 클라이언트는 즉시 붉은 방패 화면(`BlockedScreen`)으로 전환됩니다.
   * 관리자 대시보드 감사 로그에서 **붉은색 배경(#fee2e2)**으로 강조 표시되며 실시간 알림 벨이 울립니다.
2. **조건부 허용 (`STEP_UP` / 30점 이상 또는 BYOD 기기)**:
   * 미등록 기기, 신규 IP, 심야 접속 등 위험도가 감지되거나 임직원 개인 단말(BYOD)인 경우.
   * 이메일 OTP(6자리) 또는 **최초 1회 OTP 통과 시 발급된 기기 전용 64자리 비밀키(`bioToken`)가 결합된 생체 인증(FaceID/지문)**을 성공해야만 접속이 허가됩니다.
   * 관리자 대시보드 감사 로그에서 **주황/노란색 배경(#fef3c7)**으로 표시됩니다.
3. **완전 허용 (`ALLOW` / 30점 미만 정상 기기)**:
   * 회사 소유(CORPORATE) 승인 기기 및 정상 IP/시간대 접속 시 즉시 인트라넷 출입증(JWT)이 발급됩니다.

## 3. 지속적 검증 (Continuous Verification) 및 동적 통제

* **맥박(Heartbeat, `/verify-context`) 및 게이트웨이(`verifyToken`) 단일 쿼리 검증:**
  * 클라이언트가 30초 주기(`ztna-client/hooks/useHeartbeat.ts`)로 호출하며, 정책 서버와 게이트웨이 모두 **`users` + `devices` + `token_blacklist` 단일 `LEFT JOIN` 쿼리 1회**로 토큰 폐기 여부, 기기 승인 상태(`APPROVED`), 계정 활성 여부(`is_active`), 소유 형태(`BYOD`/`CORPORATE`), 직급/역할을 실시간 대조합니다.
  * 기기 미승인/차단 또는 계정 정지가 확인되면 토큰을 블랙리스트에 등재하고 `TERMINATE`(`revoked: true`)로 세션을 즉시 종료합니다.
  * IP가 바뀌어도(Wi-Fi ↔ LTE 전환 등) 세션은 종료하지 않고, DB의 마지막 IP만 갱신하며 `IP_CHANGED`를 응답합니다.
  * 토큰은 만료까지 5분 이하이거나 권한/소유 형태가 변경된 경우에만 재발급합니다(JWT 유효기간 15분).
  * 토큰에 서명된 `deviceId`와 요청 기기가 다르면 즉각 세션을 파기하고 토큰을 블랙리스트에 등재합니다.
* **소유 형태(BYOD) 및 모바일 캡처 통제:**
  * 개인 기기(BYOD)는 2차 인증을 통과하더라도 `allowDownload: false`가 강제 적용되어 사내 기밀문서 다운로드·업로드가 원천 차단되고 일정(`Schedule`) 탭이 제한됩니다.
  * 모바일 앱에서는 사내망(`IntranetScreen`) 진입 시 `expo-screen-capture`를 통해 OS 화면 캡처 및 녹화가 원천 차단됩니다.
* **실시간 권한(RBAC/ABAC) 동기화:**
  * 직급(`사원 Lv.1` ~ `임원 Lv.6`) 및 역할(`USER`, `ADMIN`) 변경 시 게이트웨이 응답 헤더(`x-allow-download-sync`, `x-user-position-level-sync`, `x-user-role-sync`)와 Heartbeat를 통해 토큰 재발급 전이라도 즉시 반영됩니다.
