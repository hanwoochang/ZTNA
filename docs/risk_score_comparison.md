# ZTNA 위험도 산출(CARTA) 및 대응 체계

본 문서는 ZTNA 정책 서버(`ztna-policy-server/services/riskEngine.js` 및 `controllers/authController.js`)에 구현되어 실제 동작하는 **실시간 컨텍스트 기반 위험도 평가 로직(CARTA: Continuous Adaptive Risk and Trust Assessment)**을 상세히 명세합니다.

---

## 1. 위험도 점수 산출 테이블 (Risk Assessment Rules)

| 카테고리 | 평가 항목 (컨텍스트 트리거) | 부여 점수 | 적용 및 대응 (Action) |
| :--- | :--- | :---: | :--- |
| **기기 무결성** | **OS 루팅 또는 탈옥(Jailbreak) 상태 감지** | **즉시 차단** | `forceDeny` (접근 즉시 거부, Red Shield 화면) |
| **기기 신뢰도** | **관리자에 의해 차단/해제된 기기 (`status !== 'APPROVED'`)** | **즉시 차단** | `forceDeny` 및 `+100점` |
| **기기 신뢰도** | **시스템에 처음 등록되는 미등록 기기 접속** | **+30점** | OTP 2차 인증 요구 및 어드민 승인 대기(`PENDING`) |
| **물리적 이동** | **물리적으로 불가능한 이동 속도 (1,000km/h 초과)** | **+70점** | Impossible Travel 감지, 접근 즉시 차단 (`DENY`) |
| **물리적 이동** | **비정상적인 고속 이동 패턴 (500~1,000km/h)** | **+30점** | 위험도 가산 및 2차 인증(OTP) 요구 |
| **물리적 이동** | **이전 접속지 대비 장거리 이동 (500km 초과)** | **+20점** | 위험도 가산 |
| **물리적 이동** | **이전 접속지 대비 중거리 이동 (100~500km)** | **+10점** | 위험도 가산 |
| **네트워크** | **기존 접속 이력이 없는 새로운 IP 주소 대역 접속** | **+20점** | 위험도 가산 |
| **네트워크** | **모바일 앱의 GPS 위치 정보 수집 불가/권한 거부** | **+15점** | 위험도 가산 |
| **접속 시간대** | **비정상 활동 시간대 (새벽 2시 ~ 5시 사이 접속)** | **+15점** | 위험도 가산 |
| **접속 시간대** | **업무 시간 외 접속 (09~18시 외 야간/주말)** | **+15점** | 위험도 가산 |

## 2. 보안 정책 결정 임계치 (Action Thresholds)

산출된 총 위험도 점수(0 ~ 100점) 및 기기 상태에 따라 다음과 같은 3단계 정책(NIST SP 800-207 준수)이 자동 결정됩니다:

```
[ 점수 기준 ]
 0점 ──────────────── 30점 ──────────────── 70점 ────────────── 100점
  │      ALLOW         │      STEP_UP        │       DENY         │
  │   (정상 출입증)     │  (OTP / 생체 인증)    │  (접속 차단 / 튕김)  │
```

1. **즉시 차단 (`DENY` / `forceDeny` / 70점 이상)**:
   * 루팅, 차단된 기기, Impossible Travel 등 심각한 위협 발생 시 토큰 발급을 거부하고 접속을 즉시 차단합니다.
   * 클라이언트는 즉시 붉은 방패 화면(`BlockedScreen`)으로 전환됩니다.
   * 관리자 대시보드 감사 로그에서 **붉은색 배경(#fee2e2)**으로 강조 표시되며 실시간 알림 벨이 울립니다.
2. **조건부 허용 (`STEP_UP` / 30점 이상 또는 BYOD 기기)**:
   * 미등록 기기, 신규 IP, 심야 접속 등 위험도가 감지되거나 임직원 개인 단말(BYOD)인 경우.
   * 이메일 OTP(6자리) 또는 기기 생체 인증(FaceID/지문)을 성공해야만 접속이 허가됩니다.
   * 관리자 대시보드 감사 로그에서 **주황/노란색 배경(#fef3c7)**으로 표시됩니다.
3. **완전 허용 (`ALLOW` / 30점 미만 정상 기기)**:
   * 회사 소유(CORPORATE) 승인 기기 및 정상 IP/시간대 접속 시 즉시 인트라넷 출입증(JWT)이 발급됩니다.

## 3. 지속적 검증 (Continuous Verification) 및 동적 통제

* **맥박(Heartbeat, `/verify-context`) 검증:**
  * 1회성 로그인이 아닌, 세션 유지 중에도 주기적으로 네트워크 IP와 기기 승인 상태를 지속 대조합니다.
  * 토큰에 서명된 `deviceId`와 실제 요청 기기가 다르면 즉각 세션을 파기하고 토큰을 블랙리스트에 등재합니다.
* **소유 형태(BYOD)에 따른 다운로드 통제:**
  * 개인 기기(BYOD)는 2차 인증을 통과하더라도 토큰 페이로드에 `allowDownload: false`가 설정되어 사내 기밀문서 다운로드가 원천 차단됩니다.
* **실시간 권한(RBAC) 동기화:**
  * 직급(사원~임원) 및 역할(USER, FINANCE, ADMIN) 변경 시 게이트웨이 및 세션 연장 과정에서 실시간으로 권한이 갱신 반영됩니다.
