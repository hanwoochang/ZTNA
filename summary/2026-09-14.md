# ZTNA Project Development Summary (2026-09-14)

오늘 진행된 ZTNA(Zero Trust Network Access) 모바일 애플리케이션 프론트엔드 및 백엔드 주요 개발 내역을 요약합니다.

## 1. UI/UX 및 편의성 개선 (Mobbin Design)
- **SVG 아이콘 전면 도입:** 기존 텍스트 이모지를 제거하고, 깔끔한 모노톤의 SVG 아이콘(Mobbin 스타일)을 적용하여 디자인 완성도를 높였습니다.
- **자동 로그인 활성화:** 사용자의 요청에 따라 자동 로그인 기능을 다시 활성화했습니다.
- **키보드 가림 현상 수정:** 안드로이드 환경에서 로그인 시 키패드가 입력창을 가리는 현상을 `KeyboardAvoidingView`와 레이아웃 구조 개선으로 해결했습니다.
- **보안 IP 수집 대기 처리:** 기기 정보(IP 등)를 수집하는 동안에는 로그인을 차단하고 알림을 띄우는 보안 밸리데이션을 추가했습니다.

## 2. 기밀 게시판(Notice Board) 고도화 및 DB 연동
- **스와이프 삭제(Swipe-to-Delete):** `react-native-gesture-handler`를 도입하여, 게시물을 옆으로 밀면 삭제 버튼(휴지통)이 나타나는 모바일 친화적인 UX를 구현했습니다.
- **게시글 수정 기능:** 본인이 작성했거나 관리자(보안팀, 인사팀)인 경우에만 게시물 상세 보기 모달 우측 상단에 '수정' 아이콘이 나타나도록 권한(Permission) 기반 UI를 추가했습니다.
- **MySQL 데이터베이스 영구 연동:** 
  - 백엔드(`target.js`)에서 게시물을 메모리 배열이 아닌 **MySQL DB(`notices` 테이블)**에 저장하도록 전면 개편했습니다.
  - SQL 인젝션 해킹을 방어하기 위해 모든 쿼리에 파라미터화된 쿼리(Parameterized Query)를 적용하여 보안성을 극대화했습니다.

## 3. 사내 일정(Schedule) 캘린더 기능 신설 및 DB 연동
- **캘린더 탭 추가:** 하단 네비게이션에 `Schedule` 탭을 추가하고, `react-native-calendars` 라이브러리를 사용해 달력 UI를 구현했습니다.
- **디자인 커스터마이징:** 달력 크기를 넓히고, 모서리를 둥글게(24px) 처리했으며, 영문 월 표기를 직관적인 숫자(예: '2026년 09월')로 변경했습니다.
- **인라인(Inline) 일정 관리 기능:** 
  - 팝업창(모달) 대신, **달력 날짜를 터치하면 하단 빈 공간에 해당 날짜의 일정이 부드럽게 나타나는 방식**으로 UI를 변경했습니다.
  - 날짜별 일정을 자유롭게 추가하고 삭제할 수 있으며, 일정이 등록된 날짜에는 달력에 푸른색 점(Dot)이 표시되도록 상호작용을 구현했습니다.
- **캘린더 MySQL 연동:** 게시판과 동일하게 일정도 DB(`events` 테이블)에 실시간으로 연동되어 영구 보존되도록 백엔드(`target.js`) API를 구축했습니다.

## 4. 권한 기반 접근 제어(RBAC) 및 보안 논리 고도화
- **작성자 소유권(Ownership) 검증 로직 추가:** 
  - 게시물과 캘린더 일정을 삭제(DELETE)/수정(PUT)할 때, 백엔드에서 현재 사용자(`currentUser`)와 작성자(`author`)를 비교하여 일치하지 않으면 403 Forbidden 에러로 원천 차단했습니다.
  - 프론트엔드에서도 남이 쓴 글이나 일정에는 아예 '휴지통'이나 '스와이프 삭제'가 보이지 않도록 UI 렌더링을 통제했습니다.
- **DB 스키마 정규화 (무결성 강화):** 게시글 수정 시 날짜 필드에 문자열을 갖다 붙이던 임시 방편을 폐기하고, `is_edited`라는 boolean형 전용 컬럼을 DB에 추가(Migration)하여 데이터 정규화를 완벽히 수행했습니다.

## 5. 엔터프라이즈 모바일 보안 기능 (App Security) 추가
- **화면 캡처 원천 차단:** `expo-screen-capture`를 도입해 기밀망(`IntranetScreen`) 진입 시 모바일 OS 레벨에서 화면 캡처 및 녹화가 불가능하도록 방지했습니다.
- **생체 인증(Biometrics) 도입:** 
  - `expo-local-authentication` 모듈을 연동하여, ZTNA 2차 인증(Step-Up) 단계에서 귀찮은 이메일 OTP 대신 FaceID 및 지문 인식을 사용할 수 있게 되었습니다.
  - Settings 화면에 라디오 버튼을 신설해 사용자가 인증 수단(OTP vs Bio) 및 테마를 자유롭게 선택할 수 있으며, `AsyncStorage`를 통해 기기에 영구 저장되도록 구현했습니다.
  - 정책 서버에 생체 인증 전용 검증 API(`/api/verify-bio`)를 신규 개설했습니다.

## 6. 보안 코드 리뷰 및 버그 수정 (오후 세션)

### 6-1. JWT_SECRET 강화
- `ztna-policy-server/.env`, `ztna-gateway/.env` 두 파일의 JWT_SECRET을 단순 문자열에서 **128자리 랜덤 HEX** 값으로 교체했습니다.
- 두 서버가 동일한 키를 공유해야 Gateway가 Policy Server 발급 JWT를 정상 검증할 수 있음을 확인했습니다.

### 6-2. 게시판 권한 체크 로직 통일 (백엔드 ↔ 프론트엔드)
- **버그 원인:** `notice.author`(글쓴이)가 특권 계정인지 체크하여, 보안팀 글은 누구나 수정/삭제할 수 있는 취약점이 존재했습니다.
- **수정 내용:** `currentUser`(현재 로그인한 사람)가 특권 계정인지 체크하는 방식으로 백엔드 `DELETE`/`PUT` 및 프론트엔드 스와이프·수정 버튼 총 4곳을 통일했습니다.
  - 수정 전: `notice.author !== '보안팀'`
  - 수정 후: `currentUser !== '보안팀'`

### 6-3. 게시판 날짜 필드 정규화 (`is_edited` 컬럼 분리)
- **버그 원인:** 게시글 수정 시 `date` 컬럼에 `"2026-09-14 (수정됨)"` 형태로 텍스트를 붙여 날짜 정렬 및 파싱이 깨지는 문제가 있었습니다.
- **수정 내용:** `notices` 테이블에 `is_edited TINYINT(1) DEFAULT 0` 컬럼을 추가하고, `ALTER TABLE`로 기존 테이블도 자동 마이그레이션되도록 구현했습니다. `(수정됨)` 표시는 프론트에서 `is_edited` 값을 보고 조건부 렌더링합니다.

### 6-4. 일정(Events) DB 연동 및 권한 로직 통일
- 로컬 상태로만 관리되던 일정 탭을 MySQL `events` 테이블과 완전 연동했습니다.
- events `DELETE` 권한도 게시판과 동일한 방식(`currentUser !== '관리자'`)으로 통일했습니다.

### 6-5. Gateway CORS 메서드 보완
- 게시판 수정/삭제 API 추가 이후 Gateway CORS 허용 목록에 `PUT`, `DELETE`가 누락되어 있었습니다.
- `methods: ['GET', 'POST', 'PUT', 'DELETE']`로 수정했습니다.

### 6-6. Heartbeat 간격 최적화
- `useHeartbeat.ts`의 서버 호출 간격을 `5초 → 30초`로 조정했습니다.
- 5초 간격은 JWT 검증 + 블랙리스트 DB 조회 + 기기 DB 조회를 매 5초마다 발생시켜 AWS 배포 시 과부하 우려가 있었습니다.

### 6-7. 생체 인증(`verify-bio`) 보안 강화
- **문제:** 기존 코드는 `otp_expiry`가 유효하기만 하면 생체 인증 없이도 API를 직접 호출하여 토큰을 발급받을 수 있는 취약점이 존재했습니다.
- **수정 내용:** `/api/verify-bio` 호출 시 `deviceId`가 DB에 `is_trusted = 1`로 등록된 신뢰 기기인지 서버에서 추가 검증합니다.
- **효과:** 생체 인증 성공 조건이 세 단계로 강화됩니다.
  1. `otp_expiry` 유효 (서버)
  2. `is_trusted = 1` 등록 기기 (서버)
  3. Secure Enclave 생체 인증 통과 (클라이언트 하드웨어)

### 6-8. API 번호 주석 정리
- `auth.js`에 `verify-bio`가 API 4로 추가됨에 따라, `session.js`의 로그아웃/Heartbeat 주석 번호를 `[API 4/5]` → `[API 5/6]`으로 정정했습니다.

- 3주차 개발 성과를 정리한 프리젠테이션 스크립트(`3주차 발표.md`)를 작성했습니다.

## 8. 모바일 사원증 및 임직원 조회 (Directory) 스와이프 기능
- **임직원 조회 기능 신설:** 기존 'Attendance(출근)' 탭을 가로형 스크롤 뷰(`ScrollView` with `pagingEnabled`)로 감싸서, 왼쪽으로 화면을 밀면(Swipe) 임직원 목록을 조회할 수 있도록 UX를 개편했습니다.
- **페이지 인디케이터(Dots) 추가:** 스와이프가 가능하다는 것을 직관적으로 알 수 있도록 출근 탭 하단 중앙에 모빈(Mobbin) 스타일의 점 2개를 추가하고, 활성화된 화면에 따라 점의 색상이 바뀌게 연동했습니다.
- **DB 연동:** `target.js`에 `GET /api/employees` 엔드포인트를 추가하여 사내망 정책서버 DB의 `users` 테이블을 조회하도록 연동했습니다.

## 9. 실시간 데이터 최신화 (새로고침 기능) 강화
- **당겨서 새로고침 (Pull-to-Refresh):** 임직원 목록(Directory) 화면 상단에 `RefreshControl`을 추가하여, 화면을 아래로 당기면 로딩 스피너와 함께 최신 데이터가 반영되도록 구현했습니다.
- **탭 이동 시 자동 새로고침 (useFocusEffect):** '출근(Attendance)', '기밀 게시판(Documents)', '캘린더(Schedule)' 탭은 사용자가 탭을 누르고 이동할 때마다 실시간으로 서버에서 최신 데이터를 긁어오도록 `useFocusEffect`를 적용했습니다. 이제 다른 직원이 쓴 글도 앱 재시작 없이 즉시 볼 수 있습니다.

## 10. 기타 UI 버그 픽스
- **PDFKit 한글 깨짐 (서버 크래시) 픽스:** `target.js`에서 PDF를 동적 생성할 때 한국어 시간(`ko-KR`) 폰트가 내장 폰트에 없어 발생하던 서버 크래시를 `en-US` 로케일 포맷으로 변경하여 해결했습니다.
- **다크모드 캘린더 색상 가림 현상 수정:** 다크모드에서 선택한 캘린더 날짜의 동그라미 배경과 글씨가 모두 흰색이라 사라지던 버그를 고치기 위해, `react-native-calendars` 설정에 고정값(배경 `#141414`, 글씨 `#ffffff`)을 강제 주입하여 해결했습니다.
- **신뢰할 수 없는 기기 생체 인식 우회:** DB가 초기화되거나 새 기기로 접속하여 `isTrustedDevice`가 `false`인 경우, Face ID 인증을 묻지 않고 즉시 이메일 OTP 화면으로 넘어가도록 로직을 다듬었습니다.
