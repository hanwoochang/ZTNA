# 2026년 11월 2일 작업 요약

## 1. 생체 인증 기기 전용 비밀키(`bioToken`) 검증 강화 (`migrate_db.js`, `authController.js`, `admin.js`, `useAuth.ts`)
*   **배경 및 목적:**
    *   기존에는 1차 로그인(`POST /api/login`) 후 모바일 OS 생체 인증 성공 여부를 서버가 암호학적으로 교차 검증할 수단이 부족하여, 공격자가 `POST /api/verify-bio`를 직접 호출해 이메일 OTP를 우회할 가능성을 원천 차단하기 위해 기기 귀속 암호화 비밀키(`bioToken`) 검증 체계를 도입함.
*   **서버 및 DB 스키마 구현 (`ztna-policy-server`):**
    *   `ztna-policy-server/scripts/migrate_db.js`의 `devices` 테이블 마이그레이션 항목에 `bio_token_hash VARCHAR(255) DEFAULT NULL` 컬럼을 추가하고 EC2 운영 DB에 반영 완료.
    *   `verifyOtp`(`POST /api/verify-otp`)에서 이메일 OTP 검증 통과 시 `crypto.randomBytes(32).toString('hex')`로 64자리(256-bit) 난수 `bioToken`을 생성하고, `bcrypt.hash(bioToken, 10)` 해시값을 `devices.bio_token_hash`에 저장한 뒤 원본 `bioToken`을 클라이언트에 반환하도록 구현.
    *   `login`(`POST /api/login`)에서 `isTrustedDevice` 판정 조건에 `Boolean(currentDevice.bio_token_hash)`를 추가하여 서버에 비밀키 해시가 등록된 기기만 생체 인증을 허용하도록 강화.
    *   `verifyBio`(`POST /api/verify-bio`)에서 클라이언트가 제출한 `bioToken`과 DB의 `devices.bio_token_hash`를 `bcrypt.compare`로 대조하며, 누락되거나 불일치할 경우 `otp_attempts`를 증가시키고 위험도 70(`DENY`) 감사 로그를 기록한 뒤 `401 Unauthorized`로 즉시 차단.
    *   관리자의 기기 차단(`PATCH /api/admin/devices/:id/revoke` in `ztna-policy-server/routes/admin.js`) 및 위험도 70점 이상 자동 차단 시 `bio_token_hash = NULL`로 초기화하여, 추후 기기가 재승인되더라도 최초 1회 이메일 OTP를 다시 거치도록 강제.
*   **클라이언트 보안 저장소 연동 (`ztna-client/hooks/useAuth.ts`):**
    *   이메일 OTP 인증 성공 시 발급받은 `bioToken`을 `Storage.setItemAsync('bio_token', ...)`(`expo-secure-store`)에 안전하게 저장하고, 차기 생체 인증 로그인 시 `Storage.getItemAsync('bio_token')`을 읽어 `POST /api/verify-bio` 요청 바디에 함께 전송하도록 구현.

## 2. DB 3단계 순차 검증 쿼리 단일화(`LEFT JOIN`) 및 오버헤드 벤치마크 재측정 (`server.js`, `authController.js`, `benchmark-overhead.js`, `OVERHEAD_BENCHMARK_REPORT.md`)
*   **단일 `LEFT JOIN` 통합 쿼리 적용:**
    *   기존 게이트웨이(`ztna-gateway/server.js` - `verifyToken`) 및 정책 서버(`ztna-policy-server/controllers/authController.js` - `verifyContext`)에서 매 요청마다 순차적으로 3회 실행하던 DB 조회(`token_blacklist` -> `devices` -> `users`)를 `users` 기준 `devices`와 `token_blacklist`를 결합한 **단일 `LEFT JOIN` 쿼리 1회**로 통합.
    *   `Server-Timing` 응답 헤더에 `db-verify;dur=...;desc="DB Single-JOIN Verify"` 지표를 반영하고 `benchmark-overhead.js`에서 자동 파싱하도록 개선.
*   **EC2 운영 서버 최적화 전(Before) vs 최적화 후(After) 실측 비교 결과 (`docs/OVERHEAD_BENCHMARK_REPORT.md`):**
    *   **PEP 순수 보안 검증 시간 (`ztna-pep` Avg):** `2.656 ms` -> **`1.851 ms`** (**`30.3%` 단축**)
    *   **PEP 내 DB 검증 소요 시간 (Avg):** `1.643 ms` (3회 합산) -> **`0.830 ms`** (1회 통합) (**`49.5%` 단축**)
    *   **경량 API (`GET /private/`) ZTNA 오버헤드:** `+4.80 ms` -> **`+3.95 ms`** (**`17.7%` 감소**)
    *   **사내 공지 조회 (`GET /private/api/notices`) 오버헤드:** `+4.31 ms` -> **`+3.53 ms`** (**`18.1%` 감소**)
    *   **동시 접속 처리량 (RPS):** `c = 1`에서 `200.5 -> 241.8 Req/sec` (**`+20.6%` 향상**), `c = 10`에서 `252.0 -> 282.4 Req/sec` (**`+12.1%` 향상**), `c = 50`에서 `266.2 -> 291.1 Req/sec` (**`+9.4%` 향상**) 달성.
    *   **Heartbeat 갱신 주기 (`POST /api/verify-context`):** `p95` 지연시간이 `7.88 ms -> 5.92 ms`로 **`24.9%` 단축**.
