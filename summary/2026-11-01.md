## 1. 사내 일정(`Schedule`) 권한 정책 통일 및 실시간 권한 동기화 보강 (`eventsController.js`, `ScheduleTab.tsx`, `useIntranet.ts`)
*   **백엔드 일정 등록/수정/삭제 RBAC·ABAC 검증 통일 (`ztna-gateway/controllers/eventsController.js`):**
    *   **원인 규명:** 게시물(`notices`)은 `대리 이상(position_level >= 2)`부터 작성 가능하도록 제한되어 있었으나, 일정(`events`) 등록(`createEvent`)에는 직급 검증 로직이 누락되어 `사원(position_level = 1)`도 일정을 등록할 수 있던 문제 확인.
    *   **조치 내용:**
        *   `createEvent`에 `userRole !== 'ADMIN' && userPos < 2` 검증을 추가하여 `사원` 계정의 일정 등록 시도 시 `403 Forbidden`(`일정 등록 권한이 없습니다 (대리 이상 가능).`)을 반환하도록 통일.
        *   `deleteEvent` 및 `updateEvent`도 게시물 정책과 동일하게 `대리 이상(userPos >= 2)`은 본인이 등록한 일정(`event.author === currentUser`)을 수정·삭제할 수 있고, `과장 이상(userPos >= 3)` 또는 `ADMIN`은 모든 일정을 수정·삭제할 수 있도록 개선.
*   **클라이언트 UI 제어 및 전 탭 직급 동기화 (`ztna-client/components/tabs/ScheduleTab.tsx`, `ztna-client/hooks/useIntranet.ts`):**
    *   `ScheduleTab.tsx`에서 `canCreateEvents`(`userRole === 'ADMIN' || userPositionLevel >= 2`) 조건에 따라 `사원` 계정에는 입력창 비활성화 및 `"일정 등록은 대리 이상부터 가능합니다."` 안내 문구를 표시하고, 버튼 클릭 시 권한 안내 알림이 표시되도록 처리(웹 `window.alert` 및 모바일 `Alert.alert` 모두 지원).
    *   `useIntranet.ts`의 `fetchDocuments`, `fetchEvents`, `fetchEmployees`에도 `handleSyncHeader(response)` 호출을 추가하여 사용자가 어느 탭에 머물러 있더라도 관리자 대시보드에서 변경한 직급/역할/다운로드 권한이 즉시 반영되도록 보강.

## 4. 대규모 부하 테스트(`Autocannon` & `k6`) 구축 및 EC2 운영 서버 디스크/로그 최적화
*   **벤치마크 스크립트 정밀도 개선 (`ztna-gateway/benchmark-overhead.js`):**
    *   4번 실험(Heartbeat 토큰 재발급) 루프에서 매회 새로운 `jti`를 가진 만료 임박 토큰(`issueToken(actor, '3m')`)을 발급하도록 수정하여 100회 반복 시 블랙리스트 충돌 없이 순수 재발급 연산 오버헤드와 페이로드 바이트(`skipPayloadBytes` vs `reissuePayloadBytes`)를 분리 측정하도록 개선.
    *   전 실험 구간에 HTTP 비정상 응답(`statusCode >= 400`) 카운터를 추가하고, `http`/`https` 프로토콜 자동 분기를 지원하도록 고도화.
*   **Autocannon 극한 스트레스 테스트 (`ztna-gateway/run-autocannon-stress.js`):**
    *   동시 접속 `c = 10, 50, 100` 조건에서 Direct 타겟과 ZTNA Gateway 경유 경로를 연속 비교하는 스크립트 작성(`p97_5` 백분위수 매핑, 복합 에러/타임아웃 집계, 단계 간 1.5초 소켓 쿨다운 적용).
    *   초당 수천 건의 무휴지(Zero Think-Time) 극한 부하에서도 에러/타임아웃 `0건`으로 초당 약 `290 RPS`를 처리하며, MySQL 커넥션 풀(`connectionLimit: 10`) 대기열이 고부하 시 주요 지연 요인임을 규명.
*   **k6 가상 사용자(VU) 점진적 시나리오 부하 테스트 (`ztna-gateway/k6-load-test.js`, `ztna-gateway/run-k6.js`):**
    *   EC2에 `k6 v0.54.0`을 설치하고, 45초 동안 가상 사용자(VU)가 `10명 -> 50명 -> 100명`으로 점진적 증가(Ramp-up)하며 50ms 간격(`sleep(0.05)`)으로 공지사항 API를 호출하는 현실적 시나리오 테스트 수행.
    *   **실측 결과:**
        *   **Direct (No-ZTNA):** 총 `26,798건` 처리 (`594.8 req/s`), 평균 `18.77 ms`, `p50 11.70 ms`, `p95 56.28 ms`, 실패율 `0.00%`
        *   **ZTNA Gateway (PEP 경유):** 총 `10,226건` 처리 (`227.0 req/s`), 평균 `131.98 ms`, `p50 122.34 ms`, `p95 292.70 ms`, 최대 `335.85 ms`, 실패율 `0.00%`
    *   동시 접속자 100명 환경에서도 상위 95% 사용자가 `0.29초` 이내에 응답을 받는 안정적인 성능을 입증.
*   **EC2 디스크 정리 및 `pm2-logrotate` 자동화 적용:**
    *   불필요한 패키지 캐시(`apt clean`), 구버전 비활성 Snap 리비전, 시스템 저널 로그, PM2 누적 로그를 정리하여 루트 디스크 여유 공간 확보.
    *   `pm2-logrotate` 모듈을 설치 및 설정(`max_size: 10M`, `retain: 3`)하여 반복적인 부하 테스트 시에도 로그 파일 무한 증식으로 인한 디스크 고갈을 원천 방지.
