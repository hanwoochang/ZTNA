## 4. 전 구간 코드베이스 보안 감사 및 심층 보안 패치
*   **X-Forwarded-For(XFF) 헤더 스푸핑 원천 차단 (`utils/ip.js`, `server.js`, `target.js`, `attendanceController.js`, `accessLogger.js`, `documentsController.js`):**
    *   Nginx 기본 `$proxy_add_x_forwarded_for` 환경에서 `x-forwarded-for.split(',')[0]`을 읽을 경우 공격자가 임의의 XFF 헤더를 주입해 Rate Limiter 우회, 위험도 엔진 IP 비교 우회, 감사/근태 로그 IP 위조가 가능했던 취약점 해결.
    *   정책 서버, 게이트웨이, 타겟 서버에 `app.set('trust proxy', 1)`을 설정하고, Nginx가 직접 덮어쓰는 `x-real-ip` 헤더 및 검증된 `req.ip`만 참조하도록 `getClientIp(req)` 유틸리티로 전 구간 일원화.
*   **게이트웨이 단말기 식별자(`deviceId`) 필수 검증 (`ztna-gateway/server.js`):**
    *   단말기 정보가 없는 관리자 웹 콘솔 전용 토큰으로 사내 인트라넷(`/private`)에 우회 진입할 수 없도록, 게이트웨이 `verifyToken`에서 `!decoded.deviceId`인 경우 즉시 `403 Forbidden`으로 차단.
*   **미사용 공개 회원가입 API 제거 (`routes/auth.js`, `controllers/authController.js`):**
    *   외부인의 임의 계정 생성을 방지하기 위해 인증 없이 열려 있던 `POST /api/signup` 엔드포인트를 제거하고, 관리자 콘솔(`POST /api/admin/users`)을 통해서만 임직원 계정이 생성되도록 일원화.
*   **정지된 계정(`is_active === 0`) 전 구간 실시간 차단:**
    *   일반 로그인(`login`), OTP 인증(`verifyOtp`), 생체 인증(`verifyBio`), Heartbeat(`verifyContext`), 게이트웨이 프록시(`ztna-gateway/server.js`), 관리자 미들웨어(`middleware/isAdmin.js`) 전 구간에서 `is_active === 0` 여부를 실시간 확인하여 정지된 계정의 접근 및 활성 세션을 즉시 차단(`TERMINATE`).
*   **2차 인증(`verifyBio`, `verifyOtp`) 보안 및 감사 로그 보강 (`routes/auth.js`, `controllers/authController.js`):**
    *   `POST /api/verify-bio` 라우트에 `otpLimiter` 및 `otp_attempts >= 5` 횟수 초과 검증을 적용하고, 이메일 OTP 및 생체 인증 성공/실패 시 `access_logs`에 감사 로그를 기록하도록 보완.
*   **기밀문서 업로드 사전 권한 검사 및 고아 파일 방지 (`routes/documents.js`, `controllers/documentsController.js`, `config/multer.js`):**
    *   `upload.single('file')`이 디스크에 파일을 저장하기 전에 먼저 BYOD 여부와 직급(과장 이상)을 검사하는 `checkUploadPermission` 미들웨어를 배치하여 무권한 파일 업로드를 사전 차단.
    *   파일 크기 제한(`20MB`) 초과(`LIMIT_FILE_SIZE`) 시 JSON 응답(`413`)을 반환하는 에러 핸들러를 추가하고, 제목 누락이나 DB 오류 시 임시 업로드 파일을 즉시 삭제(`unlink`)하도록 개선.
*   **Heartbeat 토큰 재발급 최적화 및 블랙리스트 타이머 예외 처리 (`controllers/authController.js`, `server.js`):**
    *   `POST /api/verify-context` 호출 시 `token_blacklist` 등재 여부를 최우선 검사하고, 만료가 5분 이하로 남았거나 권한/소유 형태가 변경된 경우에만 새 토큰을 발급하도록 최적화.
    *   1시간 주기 만료 블랙리스트 토큰 정리 `setInterval` 내부에 `try/catch`를 추가하여 DB 일시 오류 시 프로세스 비정상 종료를 방지.
*   **CORS 허용 출처 제한 및 500 에러 내부 메시지 은닉:**
    *   정책 서버 및 게이트웨이의 CORS 허용 출처를 공식 도메인(`https://ztna-core.duckdns.org`)과 로컬 개발 환경으로 제한.
    *   500 에러 응답 시 내부 DB 에러 원문(`error.message`) 노출을 제거하고 서버 콘솔에만 기록하도록 수정.
