# ZTNA 개발 일일 보고서

## 📌 오늘 완료한 작업 개요
ZTNA v2.0 마일스톤의 **1주차 목표인 'Target Server(사내망) 비즈니스 API 개발'**을 1단계부터 6단계까지 완벽하게 마무리했습니다.

---

## 📝 1. 수정 및 추가된 코드 내역 (What & Why)

### (1) 데이터베이스 스키마 및 자동화 스크립트 추가
* **수정 파일**: `ztna-gateway/db_v2_schema.sql`, `ztna-gateway/init_db.js`
* **왜 사용했는가?**: 기밀문서 열람 기록과 모바일 사원증 출퇴근 기록을 영구적으로 저장할 공간(테이블)이 필요했습니다. MySQL 앱에서 직접 쿼리를 치는 대신, 프로젝트에 스키마 파일(`.sql`)을 남기고 Node.js 스크립트(`init_db.js`)로 자동 실행하게 만들어 **형상 관리와 배포 자동화**를 용이하게 했습니다.

### (2) ZTNA Gateway 헤더 주입 (Proxy Middleware)
* **수정 파일**: `ztna-gateway/server.js`
* **왜 사용했는가?**: 사내망 서버(`target.js`)는 외부의 접근이 차단되어 있고 JWT 해독 능력이 없습니다. 따라서 문지기인 Gateway가 JWT를 해독하여 추출한 사용자 식별 정보(`userId`, `email`)를 HTTP Header(`x-user-id`, `x-user-email`)에 꼬리표처럼 달아 사내망 서버로 전달하도록 프록시 로직을 수정했습니다.

### (3) Target Server 공통 접근 로그 전역 미들웨어
* **수정 파일**: `ztna-gateway/target.js`
* **왜 사용했는가?**: 보안 등급이 높은 사내망이므로 "누가, 언제, 어디서(IP), 어떤 API를" 호출했는지 무조건 기록으로 남겨야 합니다. 이를 위해 모든 API 호출보다 앞서 실행되는 전역 미들웨어를 만들어 `intranet_access_logs` 테이블에 자동 로깅되도록 했습니다.

### (4) 기밀 문서 다운로드 API (동적 PDF 생성)
* **수정 파일**: `ztna-gateway/target.js` (`GET /api/documents/secret.pdf`)
* **왜 사용했는가?**: 정적 파일을 단순히 응답하면 문서가 유출되었을 때 출처를 알 수 없습니다. `pdfkit` 라이브러리를 도입하여, 문서를 다운로드하는 **요청 시점에 실시간으로 사용자의 이메일, IP, 시간을 붉은색 워터마크로 문서에 합성**하여 스트리밍 방식으로 반환하도록 구현했습니다.

### (5) 모바일 사원증 출퇴근 API
* **수정 파일**: `ztna-gateway/target.js` (`POST /api/attendance/check-in`, `check-out`)
* **왜 사용했는가?**: 사용자가 출퇴근 버튼을 누르면 `attendance_logs` 테이블에 시간을 기록합니다. 특히 하루에 출근 버튼을 여러 번 누르는 오류를 방지하기 위해 데이터베이스의 `ON DUPLICATE KEY UPDATE` 로직을 사용하여, 출근 시간은 최초 1회로 고정하고 퇴근 시간만 최신으로 갱신되도록 똑똑하게 구현했습니다.

## 💻 2. 오늘 사용한 주요 MySQL 명령어 정리

데이터베이스 상태를 확인하고 비우기 위해 터미널 및 MySQL 앱에서 사용했던 명령어들입니다.

### 테이블 목록 및 구조 확인
```sql
USE ztna;
SHOW TABLES;                       -- 전체 테이블 목록 보기
DESCRIBE intranet_access_logs;     -- 테이블의 컬럼(열) 구조 상세보기
DESCRIBE attendance_logs;
```

### 쌓인 데이터(로그) 조회하기
```sql
USE ztna;
SELECT * FROM intranet_access_logs ORDER BY id DESC;  -- 최근 기밀문서 접근 내역 조회
SELECT * FROM attendance_logs ORDER BY id DESC;       -- 최근 출퇴근 기록 조회
```

### 데이터 초기화 (TRUNCATE)
테이블의 구조(틀)는 그대로 남겨두고, 안에 들어있는 데이터와 번호(ID)만 깔끔하게 비우는 명령어입니다.
```sql
USE ztna;

-- [선택 1] 오늘 테스트한 로그만 초기화
TRUNCATE TABLE intranet_access_logs;
TRUNCATE TABLE attendance_logs;

-- [선택 2] 모든 유저 및 기기 정보까지 완전 초기화 (주의 필요)
SET FOREIGN_KEY_CHECKS = 0;  -- 관계가 얽혀있는 테이블도 강제 삭제 허용
TRUNCATE TABLE intranet_access_logs;
TRUNCATE TABLE attendance_logs;
TRUNCATE TABLE devices;
TRUNCATE TABLE users;
SET FOREIGN_KEY_CHECKS = 1;  -- 제약 조건 복구
```

## 🚀 3. 오늘 완료한 작업 (UI/UX 및 모바일 클라이언트 고도화)

### (1) 전역 테마 (다크 모드) 엔진 구현
* **수정/생성 파일**: `hooks/useTheme.tsx`, `app/_layout.tsx`, `styles/styles.ts`
* **왜 사용했는가?**: 시스템 설정과 동기화되거나 사용자가 직접 라이트/다크 모드를 강제할 수 있는 기능이 필요했습니다. `AsyncStorage`로 설정을 영구 저장하고, 정적이었던 `styles.ts`를 `useAppStyles` 훅으로 개편하여 테마 변경 시 앱 전체의 색상이 즉시 반응하도록 동적 스타일링으로 리팩토링했습니다.

### (2) 화면 전환 애니메이션 적용
* **수정 파일**: `screens/LoginScreen.tsx`, `OtpScreen.tsx`, `BlockedScreen.tsx`
* **왜 사용했는가?**: 딱딱한 앱 진입 경험을 개선하기 위해 리액트 네이티브 내장 `Animated` API를 사용했습니다. 각 화면의 성격에 맞게 페이드 인(Fade-in), 튀어오르기(Spring), 확대 경고(Scale) 효과를 부여하여 시각적 완성도를 높였습니다.

### (3) 사내망(Target Server) 비즈니스 로직 연동
* **수정/생성 파일**: `hooks/useIntranet.ts`, `components/SkeletonLoader.tsx`, `screens/IntranetScreen.tsx`
* **왜 사용했는가?**: 이전에 백엔드에 만들어둔 출퇴근 및 파일 다운로드 API를 모바일 UI에 부착했습니다. 통신 지연 시 사용자를 안심시키기 위한 뼈대 로딩(`SkeletonLoader`)을 적용하고, 모바일 샌드박스에서 파일 저장을 처리하기 위해 `expo-file-system`과 기기 기본 공유 창을 띄우는 `expo-sharing`을 조합했습니다.

### (4) AI 에이전트 커스텀 규칙 강화
* **수정 파일**: `.agents/AGENTS.md`
* **왜 사용했는가?**: 코드를 무작정 수정하는 대신, 변경된 코드 내역과 그 사유(What & Why)를 다음 단계 진행 전에 사용자에게 먼저 요약 보고하도록 `Proactive Code Explanation` 규칙을 추가하여 협업 투명성을 높였습니다.

### (5) 프레임워크 및 런타임 호환성 해결 (트러블슈팅)
* **내용**: 스마트폰의 `expo-go` 앱과 개발 서버 간의 버전 충돌 문제를 해결하기 위해, 패키지들을 최신 버전으로 강제 업데이트(`npm install expo@latest`, `npx expo install --fix`)했습니다. 또한 최신 Expo가 요구하는 Node.js 최소 스펙을 충족하기 위해 Windows `winget`으로 Node.js 버전을 LTS로 자동 업그레이드했습니다.

### (6) Expo Router SDK 56 구조 변경 대응 (트러블슈팅)
* **수정 파일**: `app/_layout.tsx`
* **왜 사용했는가?**: Expo SDK 56 버전부터 `expo-router`가 React Navigation의 테마를 직접 임포트하는 방식을 금지하면서 앱 빌드가 충돌했습니다. 이를 해결하기 위해 `<NavigationThemeProvider>` 래퍼를 제거하고 `<Stack screenOptions>` 속성을 통해 다크 모드 색상을 네이티브로 직접 주입하는 최신 문법으로 코드를 개편했습니다.

### (7) 로컬 네트워크 타임아웃 오류 해결 (트러블슈팅)
* **수정 파일**: `constants/config.ts`
* **왜 사용했는가?**: 스마트폰(Expo Go)이 PC의 백엔드 서버에 접속하려면 정확한 IP가 필요한데, 공유기 환경 변화로 PC의 할당 IP가 변경되면서 통신 실패가 발생했습니다. `ipconfig`로 현재 PC의 올바른 내부 IP 주소를 찾아내어 `SERVER_IP` 환경 변수를 최신화함으로써 통신을 복구했습니다.

### (8) 데이터베이스 조회 SQL 쿼리 교정 (트러블슈팅)
* **수정/확인 내용**: `attendance_logs` 조회 쿼리문 수정
* **왜 사용했는가?**: 날짜 컬럼을 예약어 충돌을 피해 `date_record`로, 사용자 식별자를 `user_id`로 설계했던 1주차 스키마 구조(`db_v2_schema.sql`)를 재확인하고, 이에 맞게 `SELECT` 쿼리문을 교정하여 출퇴근 기록이 정상적으로 데이터베이스에 적재되었음을 검증 완료했습니다.
