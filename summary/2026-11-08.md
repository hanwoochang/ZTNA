## 2. 모바일 앱(`ztna-client`) 실내 GPS 지연(20초 멈춤) 해결 및 신규 APK 빌드
- **배경:** 모바일 앱에서 로그인 버튼을 누를 때 실내(와이파이 연결 상태 포함)에서 안드로이드 `Location.getCurrentPositionAsync()`가 새 위치 이벤트를 기다리느라 최대 20초 이상 응답이 지연되며 로그인이 멈추는 현상이 확인됨.
- **원인 분석:**
  - `ztna-client/app/index.tsx`에서 앱 최초 실행 시 이미 위치를 수집했음에도 로그인 버튼 클릭 시마다 `await refreshNetworkAndLocation()`을 다시 호출하여, `getCurrentPositionAsync()`가 끝날 때까지 로그인 API 전송과 로딩 스피너 표시가 블로킹되고 있었음.
  - 또한 `Promise.all([ipPromise, currentLocationPromise])` 구조로 인해 `0.1초` 만에 끝나는 IP 조회까지 GPS 측정이 완료될 때까지 화면에 반영되지 않고 대기하는 문제가 있었음.
- **수정 및 빌드 내역:**
  - `ztna-client/utils/location.ts`:
    - 실시간 GPS 측정(`getCurrentPositionAsync`)에 **`2.5초` 타임아웃(`Promise.race`)**을 적용하여 실내에서도 절대 2.5초 이상 블로킹되지 않도록 개선.
    - 2.5초 초과 시 안드로이드 OS의 **최근 5분 이내(`maxAge: 300000`) 유효 캐시 좌표(`getLastKnownPositionAsync`)** 및 앱 내 최근 5분 메모리 캐시를 즉시 반환하도록 구현하여 위치 정확도(현재 건물 좌표)를 100% 유지하면서 20초 지연을 제거함.
  - `ztna-client/app/index.tsx`:
    - IP 주소 조회 완료 시 GPS 완료를 기다리지 않고 즉시 `setIpAddress`를 갱신하도록 분리.
    - 이미 수집된 `location`이 존재하는 경우 로그인 버튼 클릭 즉시 서버로 로그인 요청을 전송하고 백그라운드에서 컨텍스트를 갱신하도록 최적화.
