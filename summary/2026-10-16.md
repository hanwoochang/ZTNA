## 2. Nginx SSL 종단(Termination) 및 통합 리버스 프록시 아키텍처 수립
*   **통합 관문 리버스 프록시 구성 (`/etc/nginx/sites-available/default`):**
    *   `https://ztna-core.duckdns.org/` : 관리자 웹 SPA 정적 서빙 (`/var/www/html`)
    *   `https://ztna-core.duckdns.org/api/` : 정책 서버 (Policy Server, 127.0.0.1:3000) 프록시
    *   `https://ztna-core.duckdns.org/private/` : ZTNA 게이트웨이 (Gateway PEP, 127.0.0.1:4000) 프록시
    *   파일 업로드 용량 확장을 위해 `client_max_body_size 50M;` 적용.
*   **HTTP -> HTTPS 자동 보안 리다이렉트:**
    *   80번 포트로 들어오는 모든 평문 HTTP 요청을 `https://ztna-core.duckdns.org$request_uri` (301 Permanent Redirect)로 강제 승격.
*   **내부 기밀망(127.0.0.1:5000) 무결성 유지:**
    *   외부 요청은 Nginx가 443번 포트에서 복호화한 후 내부 로컬 루프백(`127.0.0.1`)으로만 중계하므로, 기존 기밀망 격리 및 문지기 검증 로직은 단 한 줄의 수정 없이 100% 정상 작동 보존.

*   **타임존 동기화 조치:**
    *   `timedatectl set-timezone Asia/Seoul` 명령을 통해 OS 시스템 타임존을 `KST (UTC+9)`로 변경.
    *   MySQL 데이터베이스 서비스 및 PM2 3대 프로세스 재시작을 완료하여 DB의 `NOW()` 함수와 Node.js의 `new Date().getHours()`가 모두 한국 표준시와 100% 일치하도록 보정.
