## 4. Android APK 구동 즉시 종료(Crash) 원인 규명 및 재빌드 완료
- **배경:** 신규 빌드된 APK(`4e456877`)가 안드로이드 기기에서 실행 직후 강제 종료되는 현상이 발생하여, 정상 작동하던 이전 APK(`4a2aeb2b`)와 바이너리(`DEX` 바이트코드, `AndroidManifest.xml`, `resources.arsc`) 정밀 비교 분석을 수행함.
- **원인 규명:**
  1. `ScreenCaptureModule` 네이티브 모듈은 두 APK 모두 `classes4.dex`에 정상 포함되어 있음을 확인함.
  2. 진짜 원인은 `ztna-client/app.json`에 설정되어 있던 `"experiments": { "baseUrl": "/app" }` 옵션이었음. 해당 옵션이 웹 빌드뿐만 아니라 안드로이드 네이티브 번들링에도 영향을 주어, 아이콘 폰트(`Feather.ttf` 등 81개 에셋)의 리소스 식별자가 `assets_...` 대신 `app_assets_...`로 생성됨. 이로 인해 앱 첫 화면(`LoginScreen.tsx`)에서 Feather 아이콘 로드 시 React Native의 `AssetSourceResolver`가 리소스를 찾지 못해 `Resources$NotFoundException`으로 즉시 크래시가 발생함.
  3. 추가적으로 `ztna-client/app/index.tsx`에서 초기 마운트 및 포그라운드 진입 시 `refreshNetworkAndLocation()`이 중복 호출되며 Android의 `Location.getCurrentPositionAsync()`가 경합하는 문제와 `IntranetScreen.tsx`의 `ScreenCapture` 비동기 예외 미처리 구간을 함께 확인함.
- **수정 및 재빌드 결과:**
  - `ztna-client/app.json`: `"experiments": { "baseUrl": "/app" }` 제거 및 `expo-build-properties`(`usesCleartextTraffic: true`) 복원.
  - `ztna-client/app/app.tsx` 및 `ztna-client/app/[...all].tsx`: 웹 리버스 프록시(`/app`) 하위 호환 라우트 복원.
  - `ztna-client/app/index.tsx`: `refreshInFlightRef`를 도입하여 `refreshNetworkAndLocation()` 동시 실행 방지.
  - `ztna-client/screens/IntranetScreen.tsx`: `ScreenCapture` 호출부에 `.catch(() => {})` 안전장치 추가.
  - EAS Build를 통해 신규 Android APK 빌드 완료:
    - **Build ID:** `cdbd5cc8-2edb-4746-b4e9-7ae3e88fbd3c`
    - **다운로드 링크:** `https://expo.dev/artifacts/eas/wv50VtN3zU6nRUQNUdqlMSEQ9hVr8vTGP5S2ySYN34I.apk`
  - `docs/APP_INSTALL_GUIDE.md` 내 설치 링크 및 빌드 ID 업데이트 완료.
