# 2026년 10월 4일 작업 요약

## 1. ZTNA 정책 서버 (Policy Server) 기능 고도화
오늘 작업에서는 ZTNA 아키텍처의 핵심인 '검증되지 않은 접근 차단'과 '감사(Audit) 추적' 기능을 프로덕션 레벨로 크게 끌어올렸습니다.

### 주요 변경 사항
- **기기 상태(Device Status)의 3단계 세분화**: 
  - 단순 `is_trusted (0/1)` 이분법 구조에서 `status ('PENDING', 'APPROVED', 'BLOCKED')` 3단계 체계로 롤백 및 고도화했습니다.
  - 신규 기기는 PENDING(대기), 인가된 기기는 APPROVED(승인), 위반 기기는 BLOCKED(차단)으로 명확히 라이프사이클이 나뉘었습니다.
- **`forceDeny` (즉시 차단) 로직 도입**: 
  - `riskEngine.js`와 `auth.js`에 `forceDeny` 플래그를 도입하여, 동적 위험도 점수 누적(위치/시간)과 명시적 즉시 차단(블랙리스트/루팅) 로직을 아키텍처 상 완벽히 분리했습니다.
- **JWT 토큰 탈취 방지 (Token Theft Detection)**: 
  - `/verify-context` (Heartbeat) 검증 시, JWT에 기록된 `deviceId`와 실제 요청을 보낸 기기의 `deviceId`를 비교하는 로직을 추가했습니다.
  - 만약 불일치할 경우 해킹/탈취 시도로 간주하고 즉시 해당 토큰을 `token_blacklist`에 등록하여 세션을 영구 폐기합니다.
- **관리자 콘솔 무차별 대입 방어 및 감사 로그**: 
  - `/admin-login` 엔드포인트에 `loginLimiter`를 적용하여 브루트 포스(무차별 대입) 공격을 차단했습니다.
  - 관리자 로그인의 성공/실패 여부를 막론하고 모든 접근 시도(비밀번호 오류, 권한 없음 등)를 `access_logs`에 기록하여 규정 준수(Compliance)를 달성했습니다.

## 2. 관리자 대시보드 (Admin Web) 기기 삭제 기능 추가
- **하드 삭제(Hard Delete) API 구현**:
  - `admin.js`에 `DELETE /api/admin/devices/:id` 라우터를 추가하여, 데이터베이스(`devices` 테이블)에서 기기 정보를 영구적으로 삭제하는 기능을 추가했습니다.
  - 삭제된 기기가 다시 접근할 경우 '미등록 기기(위험도 +30점)'로 인식되어 PENDING 상태로 처음부터 다시 승인을 받아야 합니다.
- **관리자 웹 UI 업데이트 (`App.tsx`)**:
  - 기존 폰트 및 디자인(비율/크기)을 고정한 상태에서, 단말 자산 페이지의 액션 영역에 [삭제] 버튼을 추가했습니다.
  - 실수 방지를 위해 "정말 영구적으로 삭제하시겠습니까?" 경고창(`confirm`) 안전장치를 추가했습니다.

## 3. 대화 내용 및 피드백 (Troubleshooting)
- 삭제 기능 테스트 중 **"삭제 실패"** 에러가 발생하는 이슈가 있었습니다.
- **원인 분석**: `devices` 테이블의 기기를 삭제할 때, 해당 기기가 이전에 남긴 로그 기록(`access_logs`의 `device_id` 외래키 참조)이 존재할 경우 참조 무결성(Foreign Key Constraint, `ER_ROW_IS_REFERENCED_2`) 위반으로 DB가 삭제를 막는 현상입니다.
- **해결 방안 (추후 과제)**:
  1. DB 외래키에 `ON DELETE CASCADE` 또는 `ON DELETE SET NULL` 옵션을 부여하여 연쇄 삭제되거나 NULL 처리되게 변경.
  2. 하드 삭제(`DELETE`) 대신 `status = 'DELETED'` 등의 소프트 삭제(Soft Delete) 도입.
